# Система плагинов сервера SkyMP

Документ описывает настройку, эксплуатацию и миграцию системы.

Новое в исходниках для v2.1.0: [Plugin Runtime Loader](docs/docs_plugin_runtime.md). Плагин может объявить подписанные клиентские/CEF-пакеты через `Runtime/manifest.json`. Лаунчер скачивает их с сервера; после первоначального базового загрузчика совместимые обновления не требуют пересборки общей runtime. Контракт подписи/путей: [misc/plugin-runtime](misc/plugin-runtime/README.md).

## Назначение

Система разделяет монолитный gamemode на небольшие дополнения.

- Плагины обнаруживаются в `Plugins/` при старте.
- Обнаружение основано на `plugin.json`, не имени папки.
- Новые по умолчанию выключены.
- Включаются панелью, запросом терминала или автоматическим режимом.

## Пути Windows/Linux

Путь относителен рабочему каталогу сервера, `process.cwd()`.

- Windows: `Server\\Plugins\\ChatServer\\plugin.json`.
- Linux: `Server/Plugins/ChatServer/plugin.json`.
- Имя папки точно `Plugins`, с сохранением регистра.
- Проверяются только непосредственные подпапки.

## Формат поставки и зависимости

Плагин поставляется распакованным каталогом:

```text
Server/
  Plugins/
    HelloPlugin/
      plugin.json
      index.cjs
      README.md
```

ZIP загрузчик не распаковывает. Обнаруживается `plugin.json`, его `name` уникален. Обычному серверному плагину не нужны собственные `.dll`, `.esp`, `.esm`.

- `kind: gamemode`: исполняемый CommonJS JavaScript, рекомендуется `index.cjs`. TypeScript сначала компилируется. Загрузчик копирует только входной файл во временный каталог и загружает как `.js`. Локальные модули/npm включайте внутрь, например esbuild `--bundle --platform=node --format=cjs`. Соседних `node_modules/` и `require('./helper.cjs')` недостаточно. `__dirname` также не указывает установленную папку; путь постоянных данных выбирайте явно.
- `kind: process`: готовая программа/Node-скрипт с `command`/`args`, запускаемая в папке плагина. Там работают локальные файлы и стандартное разрешение модулей. Зависимости поставляются либо устанавливаются заранее. Загрузчик не выполняет `npm install`/сборку. Команда, runtime и нативные зависимости должны соответствовать каждой ОС.

У process запуск определяют только `command`/`args`; `main` автоматически не исполняется.

## Панель и перезапуски

Управление — **Ресурсы → Серверные плагины**. Показываются версия, путь, текущий статус и разрешение следующего старта. Обновление каждые пять секунд; кнопка обновляет сразу, но не сканирует диск заново.

У каждого есть **Включить/Выключить**. **Включить все выключенные** разрешает все обнаруженные с существующим манифестом независимо от фильтра. **Новые при старте → Автоматически** сохраняет `pluginDiscovery.mode: "auto"` в `server-settings.json`. Впервые обнаруженные загрузятся при следующем старте; известные выключенные останутся выключены до отдельного/группового разрешения.

Чтение требует `canViewLogs`, запись — `canConsole`. Кнопки сохраняют `startupEnabled` в `Plugins/.discovery-state.json`, не загружают/выгружают живой код. Разрешение сохраняется, терминальный помощник при каждом старте не нужен.

| Изменение | Перезапуск |
| --- | --- |
| Обновить/включить/выключить известный плагин | Игровой сервер |
| Установить новый в `safe` | Старт для обнаружения, разрешение панелью, ещё один старт |
| Установить новый с заранее выбранным `auto` | Один старт обнаруживает и включает |
| Обновить `process` | Игровой сервер и его процесс плагина |
| Обновить пакет панели/сервера | Также перезапустить starter/панель по [инструкции](docs/docs_packaged_server_update.md) |
| Изменить Skyrim-моды/SKSE/клиент | Отдельно распространить пакеты и перезапустить клиентов с нужными файлами |

При раздельных процессах панель остаётся доступна во время игрового рестарта. Перезагрузка ПК/VPS не нужна. Игроки отключаются при рестарте игры.

Новые плагины выключены. `prompt` даёт разрешить при интерактивном первом старте; у службы обычно терминала нет. `auto` терминала не требует. Разрешения известных сохраняются при обновлении с тем же `name` и смене режима.

Сейчас нет live-upload, магазина, индивидуальных start/stop/hot reload. Watcher основного gamemode после `mp.clear()` плагины не загружает. Используйте полный рестарт игрового сервера.

## Начальное состояние обнаружения

Первый старт создаёт `Plugins/.discovery-state.json`. Поля:

- `pluginPath`: относительная папка.
- `fingerprint`: хеш манифеста/значимых входных данных.
- `version`: версия манифеста.
- `startupEnabled`: запуск при загрузке.
- `discoveredAt`, `updatedAt`: время.

Различаются известные, новые, обновлённые и удалённые плагины.

## Минимальная схема plugin.json

Обязательно:

- `name`: уникальный ключ из 1–64 символов `a-z`, `A-Z`, `0-9`, `_`, `-`.
- `version`: строка с цифрой в начале; рекомендуется SemVer.
- `kind`: `gamemode`/`process`.
- `displayName`: имя для оператора.
- `description`: краткое описание для решения/проверки.

Необязательно:

- `main`: относительный вход, по умолчанию `index.cjs`.
- `optional`: ошибка не является критической для старта.
- `startupDefault`: документальная подсказка, намеренно игнорируемая для новых.
- `command`: обязательная команда для process.
- `args`: список аргументов только process.

`displayName` — до 100 символов, `description` — до 512. `main` остаётся внутри папки; абсолютные пути/начальное `..` запрещены. Манифест до 64 КиБ текста, `args` — до 128 строк.

### Полный пример gamemode

```json
{
  "name": "emotewheel",
  "version": "1.2.0",
  "kind": "gamemode",
  "displayName": "Emote Wheel",
  "description": "Adds chat-driven emote wheel bindings",
  "main": "index.cjs",
  "optional": false
}
```

### Полный пример process

```json
{
  "name": "chat-server",
  "version": "0.4.1",
  "kind": "process",
  "displayName": "Chat Server",
  "description": "Standalone chat bridge process",
  "main": "server.mjs",
  "command": "node",
  "args": ["server.mjs"],
  "optional": true
}
```

## Последовательность старта

1. Загрузка основного `gamemodePath`.
2. Сканирование подпапок `Plugins/`.
3. Только папки с `plugin.json`.
4. Проверка схемы/хеш.
5. Сравнение состояния.
6. Сначала `pluginsLoadOrder`, затем алфавитный `name`.
7. Старт только `startupEnabled=true`.
8. Запись состояния.

Gamemode загружается через `require`. Process — через `spawn`, `cwd` равен его папке, префикс журнала `[plugin:<name>]`. При выходе дети завершаются Windows `taskkill /t /f` или Linux `SIGTERM`.

## Включение новых плагинов

По умолчанию `startupEnabled=false`. Конфигурация:

```json
{
  "pluginDiscovery": {
    "mode": "safe",
    "processCommandAllowlist": ["node", "node.exe"],
    "abortOnPluginError": true
  },
  "pluginsLoadOrder": ["core", "chat-server", "emotewheel"]
}
```

`pluginDiscovery.mode`:

- `safe`: без запроса, новые выключены.
- `prompt`: интерактивный yes/no новым.
- `auto`: включить при первом обнаружении; известным сохранить решение.

Без корректной настройки действует `safe`. `auto` подходит, если в `Plugins/` попадают только проверенные плагины.

`pluginDiscovery.processCommandAllowlist` — необязательный массив строк process. Если задан, запускаются только эти команды. Сравнивается полный `command` либо имя файла, например `node`. Без массива дополнительного ограничения нет ради совместимости.

`pluginDiscovery.abortOnPluginError`, стандарт `false`:

- `true`: остановить старт при ошибке не-optional плагина; рекомендуется рабочим серверам.
- `false`: записать ошибку и продолжить.

Исходное руководство фиксирует ограничение: временный JS-загрузчик ловит/пишет исключения внутри, поэтому bootstrap может сообщить успешную загрузку. Асинхронные ошибки process приходят позже. `running`/данная настройка не доказывают исправность всех функций; проверяйте журналы и поведение.

Для службы используйте `safe` с разрешением панели/состояния либо `auto` без терминала.

## Минимальные примеры

### Gamemode

Файлы: `Plugins/HelloPlugin/plugin.json`, `Plugins/HelloPlugin/index.cjs`.

`index.cjs`:

```js
// Die Entry-Datei wird beim Gameserver-Start einmal ausgefuehrt.
console.log("[HelloPlugin] loaded");

// Persistente Eigenschaft fuer einen moeglichen spaeteren RP-Gamemode.
mp.makeProperty("helloPluginRank", {
  isVisibleByOwner: false,
  isVisibleByNeighbors: false,
  updateOwner: "",
  updateNeighbor: ""
});
```

### Process

Файлы: `Plugins/ChatServer/plugin.json`, `Plugins/ChatServer/server.mjs`.

`server.mjs`:

```js
setInterval(() => {
  console.log("[ChatServer] heartbeat");
}, 10000);
```

## Безопасность

Всё в `Plugins/` исполняет код хоста. Не включайте неизвестное без проверки. Проверяйте до `startupEnabled=true`; манифест/вход являются доверенным кодом. Для process в production задавайте allowlist, например только `node`/`node.exe`.

## Диагностика

- Не найден: лежит ли манифест прямо в `Plugins/<Name>/`, заполнены ли поля?
- Не стартует: проверьте `main` gamemode или `command`/`args` process, журналы `[plugins]`/`[plugin:<name>]`.
- Нет запроса: режим `prompt`, запуск интерактивный/TTY?
- Процесс завис: Windows использует `taskkill /t /f`, Linux `SIGTERM`; может понадобиться свой обработчик.

## Статус в Admin API

`PATCH /api/admin/plugins/:name` с `{"startupEnabled": true}`/`false` сохраняет следующее разрешение и возвращает `restartRequired: true`. Необнаруженный получает 404. Пересканирования/живого запуска нет.

`POST /api/admin/plugins/enable-all` с `{}` разрешает обнаруженные выключенные с манифестом. Ответ — `names`, `count`, `restartRequired`, true при изменении. Пропавшие манифесты пропускаются. Повтор без новых выключенных даёт `count: 0` без записи состояния.

`GET /api/admin/plugins/settings` возвращает режим `safe`/`prompt`/`auto`; `PUT`, например `{ "mode": "auto" }`, сохраняет следующий режим, сохраняя остальные поля, включая другие ключи `pluginDiscovery`. Требуется `canConsole`.

`GET /api/admin/plugins` содержит `runtimeStatus`:

- `starting`: начало запуска.
- `running`: работает.
- `failed`: ошибка старта/работы.
- `stopped`: выключен либо корректно завершён.

До первого сообщения возможен `null`. Разрешение и работа независимы: выключенное разрешение не завершает уже работающий плагин до рестарта.

Пример:

```json
{
  "name": "chat-server",
  "startupEnabled": true,
  "runtimeStatus": {
    "name": "chat-server",
    "status": "running",
    "pid": 12345,
    "updatedAt": 1760000000000
  }
}
```

## Миграция монолитного gamemode

1. Разнести модули по папкам.
2. Создать каждому манифест.
3. Оставить `gamemodePath` основным bootstrap.
4. Стартовать с `pluginDiscovery.mode = safe`.
5. Разрешать по одному через `startupEnabled=true`.
6. При необходимости задать `pluginsLoadOrder`.

## Возможные системы

Gamemode делит глобальный `mp` и API. Возможны роли/фракции/профессии/валюты/прогресс с постоянными properties (`mp.makeProperty`, `mp.get`, `mp.set`); инвентарь/добыча, телепорты, spawn, значения акторов, revival/respawn в доступных hooks; события/клиентские реакции через `mp.makeEventSource`/properties/SkyrimPlatform; журналы и внешние связи, которые плагин создаёт сам.

Process подходит ботам, webhook, мостам чата, фоновым службам. Общего `mp` и автоматического RPC/IPC **нет**. Доступ к миру требует собственной аутентифицированной связи.

Система не добавляет функции движка, автоматическую панель каждому плагину и произвольную раздачу клиентских файлов. Модели/миры/нативные функции/модули требуют соответствующих модов/пакетов. Код, уже передаваемый property/event API, следует отличать от них.

Gamemode делит процесс/глобальные обработчики без песочницы. Перезаписанные обработчики/блокирующий код влияют на другие плагины и сервер. Нет декларативной проверки зависимостей/версий и автоматического рестарта process. Один порядок не доказывает зависимости и готовность внешней службы.

API: [серверные скрипты](docs/docs_serverside_scripting_reference.md), [properties](docs/docs_properties_system.md), [events](docs/docs_events_system.md), [respawn](docs/docs_respawn_control_system.md).

## Адаптеры голосовой активности для lipsync/proximity

**На 27 октября 2026: частично реализовано.** Есть VAD-контракт, серверная рассылка и попытка клиентской анимации. Сквозной lipsync в игре не доказан. Новая локальная YACA-bridge не включает этот путь автоматически обычным входом.

[Исследование lipsync/тест](docs/docs_voice_lipsync_status.md) описывает связь, ID, метры, тайм-ауты и сброс анимации.

### Контракт и YACA

Адаптер переводит реальные события провайдера в `VoiceActivityState`, вызывает callbacks, зарегистрированные у `VoiceActivityManager`. Файл в `Plugins/` не регистрирует адаптер автоматически.

[YacaTeamSpeakAdapter.ts](../../../skymp5-server/ts/adapters/YacaTeamSpeakAdapter.ts) имеет `handleYacaVoiceEvent(...)`, но `initialize()` не соединяется с TeamSpeak. Отдельный `SkyMP-YACA-TS` использует CEF, `TALK_STATE`/`SOUND_STATE`, `_yacaClient` без Papyrus-квеста. Необязательный `onVoiceActivity` обычным входом не подключён.

`voiceActivity.enabled: true` запускает менеджер, не устраняя разрыв. Нынешние custom-пакеты `voiceActivity`/`yaca:voiceActivity` рассылают напрямую, обходя registry/таймеры. Для полной связи нужно унифицировать отправителя/состояние.

### Проверки и границы

- Есть `GET /api/admin/voice/status`, `/speakers` с `canViewLogs`.
- Нет отдельной диагностики панели и `POST /api/admin/voice/range`.
- Здоровый адаптер/парсер не доказывает движение рта; нынешние числа говорящих ограниченно полезны.
- Клиент передаёт «говорит/не говорит» и пытается запустить диалоговую анимацию; уровней/фонем нет.

См. [Voice API](docs/docs_voice_api.md), [план](ROADMAP.md#voice--proximity-chat-sync-backlog-proposed).

## Порядок загрузки в панели

**Ресурсы → Серверные плагины** показывает позиции следующего старта. Меняйте стрелками, затем **Сохранить порядок**. Включение отдельно. Несохранённое можно отменить; фильтр не удаляет элементы. Одновременные правки дают конфликт.

ID сохраняются в `pluginsLoadOrder` файла `server-settings.json`, не затрагивая приватные параметры/моды/discovery. Службы раньше потребителей, например skymp-ui-core перед example-ui-consumer/second-ui-consumer. Без настройки действует алфавит; новые неуказанные идут после по алфавиту. Временно отсутствующие настроенные ID сохраняются. Автоматических зависимостей/hot reload нет.

`GET /api/admin/plugins/load-order` даёт порядок/ревизию с `canViewLogs`. `PUT {revision, pluginsLoadOrder}` сохраняет полный список с `canConsole`. Старая ревизия — 409, неверный/неполный список — 400. Действует со следующего старта. Установка новой панели/backend требует одного рестарта starter/панели; дальнейшая перестановка — только игры.
