# План SkyMP по идеям FiveM

План превращает ключевые архитектурные идеи и практики FiveM (`citizenfx/fivem`) в задачи SkyMP: стабильность, производительность, синхронизация игроков и автоматические ресурсы/моды.

Проверено **22 октября 2026 года**. Доказательства: [статус](docs/docs_project_status.md). Предыгровая синхронизация файлов реализована отдельным лаунчером; настоящая приёмка Skyrim/CEF/игры открыта.

## Реализованные подходы

### Архитектура property bindings

- **Реализация:** `canRespawn` для собственной серверной логики.
- **Модель:** чтение/запись через TypeScript `mp.set()`/`mp.get()`.
- **Польза:** разделение обязанностей, сложные механики вроде лечения/воскрешения без C++-монолита.
- **Вывод:** гибкие FiveM-подобные свойства дают сложную игру без разрастания архитектуры.
- **Файлы:** CanRespawnBinding.h/cpp, IsDeadBinding.cpp, SpawnDelayBinding.cpp.

### Игра через конфигурацию

- **Реализация:** `startSpawn`, `starterInventory` в server-settings.json.
- **Модель:** интерфейс настроек → CMake → runtime binding.
- **Польза:** оператор меняет spawn/начальные предметы без кода.
- **Файлы:** settings.ts, spawn.ts, generate_server_settings.cmake.

### Усиление запуска

- **Реализация:** Windows-стартеры до запуска завершают старые `dist_back/skymp5-server.js`.
- **Модель:** supervisor-подобная предварительная очистка.
- **Польза:** исключение коллизий/ошибок peer из-за оставшихся Node-процессов.
- **Файлы:** `skymp5-server/CMakeLists.txt`, `build/dist/server/launch_server.bat`.

### Независимое веб-управление r3

- **Реализация:** стартер владеет отдельными панелью и игрой.
- **Поведение:** stop/restart/crash игры сохраняют панель, настройки, логи, загрузки, вход и WebSocket; панель запускает игру снова.
- **Граница:** живые действия требуют игры; завершение всей службы останавливает оба своих процесса. Публично UDP 7777 и один HTTP(S)-TCP.
- **Доказательства:** `misc/tests/test_dashboard_runtime.cjs`, отчёты пакетов платформ и видимый браузерный отчёт r3.

## 1. API ресурсов — фаза 1 готова

**Цель:** публичные HTTP-манифест/файлы как основа FiveM-подобной автозагрузки.

- **Статус:** готово. `GET /api/launcher/manifest`, `GET|HEAD /api/launcher/files/:id` реализованы `launcherResources.ts`, зарегистрированы `ui.ts`. Плоский v1 остаётся старым лаунчерам.
- **Манифест:** пути, размеры, SHA-256, сумма, ревизия, порядок, локальные требования и необязательная runtime.
- **Скачивание:** непрозрачные ID, поток, ETag, хеш/размер и одиночный byte range.
- **Публикация:** явные `client-resources/Data/` и свои плагины/архивы. Закрытые файлы, Bethesda, код runtime и опасные пути исключены из модов.
- **См.:** [моды](docs/docs_launcher_modpacks.md), [старый API](docs/docs_resource_auto_download.md).

## 2. Панель диагностики ресурсов

**Цель:** показывать каждому ресурсу хеш/размер/тип, пропажи/повреждения и ручное обновление.

- **Статус:** частично. Список/обновление есть; полная диагностика опубликованных хешей и повреждений открыта. Ошибки публичного API не заменяют UI.
- **Трудоёмкость:** средняя.
- **Риск:** низкий, изолированная задача.
- **Файлы:** панель skymp5-front, `ui.ts`.

## 3. Синхронизация лаунчера — фаза 2 подготовки готова

**Реализовано:** до SKSE лаунчер читает v2, проверяет размер/SHA-256/игру, скачивает изменения в серверный кэш, ставит полный пакет с резервированием/восстановлением. Пути текстур/моделей/скриптов сохраняются. Ошибки запрещают активацию/старт. Каталог даёт совместимые клиент/SKSE/Address Library.

- **Код:** `skymp-client-launcher/launcher/src-tauri/src/connection.rs`, `runtime_version.rs`.
- **Доказательства:** 25 текущих Rust-тестов, шесть проверок публикации runtime, настоящий Node/Rust контракт установки/кэша/ремонта/обновления/восстановления.
- **Открыто:** настоящая Skyrim/CEF/вход-в-мир приёмка, продолжение загрузок, настраиваемые retry/backoff. Игровой установщик модов этой фазе не нужен.

## 4. Манифест и зависимости — фаза 3

**Цель:** явные зависимости, семантические версии и ограничения порядка, например `"requires": ["Skyrim.esm"]`.

- **Статус:** частично. Есть порядок, базовые проверки игры, ревизии и валидация пакетов. Нет графов, SemVer-ограничений модов и автоматического разрешения.
- **Работа/риск:** средние, затрагивают загрузку ресурсов.
- **Файлы:** `launcherResources.ts`, `data/manifest.json`, `connection.rs`, будущий resolver.

## 5. State Bags — синхронизация ключ–значение

**Цель:** лёгкое расширяемое состояние сущности/игрока/мира по примеру FiveM. Гранулярная передача уменьшает тяжёлую репликацию.

- **Работа:** высокая.
- **Риск:** средний/высокий, изменения core-sync.
- **Файлы:** skymp5-server, skymp5-client, модули сущностей.

## 6. Релевантность и перенос ownership

**Цель:** relevancy/culling и явный перенос владельца для эффективной сети/серверной авторитетности по примеру scoping/migration FiveM.

- **Работа:** высокая.
- **Риск:** высокий, центральная логика sync/ownership.
- **Файлы:** skymp5-server, skymp5-client, модули сущностей.

## Приоритеты

1. **Готово:** API фазы 1 и подготовка/установка фазы 2.
2. **Следующая приёмка:** совместимый нативный клиент, настоящий Skyrim/CEF и пакет оператора на VPS.
3. **Открыто:** полная диагностика, продолжение скачивания, вытеснение кэша.
4. **Частичная фаза 3:** сохранить порядок, добавить версии/зависимости/resolver.
5. **Позже:** State Bags, улучшения релевантности/владения.

План основан на глубоком анализе FiveM и адаптирован к проблемам/целям SkyMP. Задачи можно дополнительно разделять.
