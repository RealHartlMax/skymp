# Discord OAuth администратора

<a id="purpose"></a>

## Назначение

Документ описывает вход Discord OAuth в панель администратора SkyMP и планируемую модель эксплуатации без ручной настройки токенов и переменных окружения владельцем сервера.

<a id="current-behavior"></a>

## Текущее поведение

На странице входа два варианта:

- Имя пользователя/пароль (существующий поток)
- Кнопка Discord OAuth (новый поток)

OAuth callback сопоставляет Discord User ID с записью администратора. Если администратора с такой `discordId` нет, вход запрещён.

<a id="data-model"></a>

## Модель данных

Администраторы хранятся в `server-settings.json` через:

- `adminUiUsers` (карта профилей с ролью и необязательной `discordId`)
- `adminUiRoles` (карта ролей)
- `adminUiMasterUser` (главный администратор)

Главный администратор создаётся при первой настройке или старой миграции и сохраняется автоматически.

<a id="planned-integration-model-no-manual-token-setup"></a>

## Планируемая интеграция без ручных токенов

Цель: пользователи не добавляют собственные переменные окружения или секреты вручную.

Планируемая архитектура:

1. SkyMP поставляет встроенный модуль аутентификации администратора.
2. Инструменты платформы централизованно выдают и управляют данными OAuth-приложения.
3. После OAuth сервер получает подписанные доверенные данные вместо локального управления секретами.
4. Сопоставление (`discordId` → профиль администратора) остаётся локальным, секреты OAuth — у платформы.
5. Ротация, отзыв и истечение срока автоматически обслуживаются платформой.

<a id="why-this-model"></a>

## Причины модели

- Нет ручного управления секретами операторами
- Более простая настройка
- Меньше ошибок конфигурации
- Централизованные ротация и аудит

<a id="security-requirements"></a>

## Требования безопасности

Даже при полной интеграции обязательны:

- Проверка CSRF state при старте/callback OAuth
- Строгий список разрешённых callback URL
- Краткоживущие cookie сессии
- Проверка ролей/прав после входа
- Запрет входа несопоставленных Discord ID

<a id="migration-path"></a>

## Миграция

1. Сохранить вход по имени/паролю как резервный.
2. Добавить Discord ID каждому администратору в верхнем разделе Admins.
3. Включить интегрированный Discord OAuth для экземпляра.
4. Проверить вход сопоставленных аккаунтов Discord.
5. Позднее при желании отключить пароль для администраторов, кроме главного.

<a id="notes-for-implementers"></a>

## Примечания разработчикам

- Discord ID — неизменяемый идентификатор пользователя.
- Имя в UI — метаданные отображения, не идентичность аутентификации.
- Главный администратор всегда видим и не удаляется из списка Admins.
