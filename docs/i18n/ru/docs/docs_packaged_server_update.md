# Серверные ZIP для первой и существующей установки

> **Новое:** моды теперь находятся в `data/mods/<мод>/`; `client-resources` больше не читается. Сведения о нём на этой странице устарели. См. [моды в data/mods](docs_mod_folders.md).

Состояние на 26 октября 2026 года, r12. Для Linux x64 и Windows x64 есть по два ZIP с файлами прямо в корне:

- `skymp-server-2026-10-26-r12-<plattform>-full.zip`: полная новая установка с настройками по умолчанию, gamemode, PEX и PIN-настройкой браузером. Распакуйте в пустой каталог и добавьте свои master-файлы Skyrim.
- `skymp-server-2026-10-26-r12-<plattform>-update.zip`: только заменяемые программы, dashboard и стартеры. Для настроенного сервера; данные входа, конфигурация, сохранения и свои файлы остаются. Новая PIN-настройка не нужна.

Update ZIP не содержит `server-settings.json`, `data/` (включая PEX), `world/`, `client-resources/`, моды, плагины, `gamemode.js`. Свои `package.json`, `package-lock.json`, `.runtime/`, `.env`, журналы тоже сохраняются. Список файлов описывает только включённые программы. Оба ZIP сохраняют права исполнения Linux `.sh`. `<plattform>` — `linux-x64` или `windows-x64`.

**Новое r12:** история процессов/тиков и постоянная статистика отключений, прямые вкладки настроек, расписание перезапуска игры с часовым поясом IANA, предупреждениями и пропуском ближайшего. `DASHBOARD.md` есть в Full и Update. Сохраняйте `server-settings.json` и весь `data/`, включая расписание/историю. Заменяйте оба backend, supervisor и frontend вместе. На смартфонах управление сервером сворачивается, оставляя доступ к странице.

**Сохраняется с r11:** порядок модов в ресурсах, выбор активных плагинов в манифесте launcher и проверенные имена Steam. SteamID остаётся проверенной сервером идентичностью. `MOD-LOAD-ORDER.md` есть и в Update. Обновляйте оба backend и frontend вместе.

**Новое r10:** метрики с историей 24 часа, отдельная вкладка Discord с шаблонами status embed, предпросмотром, живым сохранением. Оба пакета содержат стандартные `server-assets/logo.png`, `server-assets/banner.png`. Свои `logo.png`/`banner.png` рядом с настройками приоритетны и не перезаписываются Update. В Full оба изображения также в корне.

Известное нативное исправление threadpool поставляется **отдельным клиентским runtime-пакетом**. Серверное обновление не меняет DLL игры. Сначала загрузите новый каталог runtime, последним его каталог выбора; см. [обновление runtime](docs_launcher_runtime_updates.md).

**Идентификатор Steam-билета r8:** auth policy v2 использует компактный идентификатор, связанный с сервером. После обновления перезапустите весь сервис и заново подключитесь текущим launcher, чтобы policy/билет совпали. Устаревший идентификатор даёт `STEAM_POLICY_CHANGED` (HTTP 409); соответствующий отказ Valve — `STEAM_TICKET_AUDIENCE_MISMATCH`. Разрешения Steam, связи аккаунтов и данные сохраняются.

**Диагностика Steam с r6, дополнена r7:** включена фиксированная классификация из `STEAM-FEHLER-2026-10-24.md`. r7 добавляет очищенное объяснение Valve до 160 символов в журнал; публичные ответы содержат только фиксированные коды и числа. Для HTTP-изменения перезапустите весь стартер/сервис с dashboard; одного игрового перезапуска недостаточно. Код показывает причину проверки; прошлый отказ VPS остаётся открытым до новой попытки на обновлённом VPS.

<a id="vor-dem-dateiaustausch"></a>

## До замены файлов

1. Сохраните весь сервер, включая `server-settings.json`, администраторов, мир, моды, скрипты, свой `gamemode.js`.
2. Остановите весь стартер/systemd-сервис. Остановка игры в dashboard не останавливает веб-сервер. Не запускайте старую и новую версии одновременно на тех же портах.
3. Сравните хеш **Update ZIP**. Затем распакуйте с заменой в существующий сервер. Full — только в новый пустой каталог: его стандартные файлы перезапишут настройки и собственные данные.

Пример после копии и полной остановки; измените пути:

```bash
unzip -o /pfad/skymp-server-2026-10-25-r11-linux-x64-update.zip -d /pfad/zum/bestehenden/server
```

Запустите прежний systemd-сервис или `sh ./start-test-server.sh` в каталоге сервера. Через SFTP передавайте **содержимое** Update ZIP с той же структурой и заменой файлов. Не удаляйте каталоги данных. Включены все текущие программы независимо от исходной r5–r10; предполагается настроенная установка с независимым dashboard.

## Обновлять совместно

В Update ZIP файлы уже отобраны. При ручной замене из Full берите вместе:

- Весь `dist_back/`, включая `skymp5-server.js`, `skymp5-admin.js`, обе source map
- Весь `ui/` и подходящий `scam_native.node`
- `server-supervisor.cjs`
- `setup-server.cjs`, `setup-web.cjs`, `launcher-connection.cjs`, `check-install.cjs`
- `setup-ui/`, `supervisor-ui/`
- `server-assets/`; свои изображения в корне сохранить
- Linux: `start-test-server.sh`, `launch_server.sh`, `bootstrap-runtime.sh`
- Windows: `start-test-server.bat`, `start-test-server.cmd`, `launch_server.bat`, `bootstrap-runtime.ps1`
- `build-manifest.json`, `release-info.json`, `QUELLSTAND.txt`, `README-TEST.md`, `DISCORD-BOT.md`, `INGAME-LOGIN.md`, `MOD-LOAD-ORDER.md`, `PORTS-VPS.md`, `UPDATE-VPS.md`, лицензии

Нативные **серверные модули** локальной r11 по содержимому совпадают с r10. Для поздних выпусков или иных исходных версий всегда берите подходящий модуль из того же полного платформенного пакета.

**Сохранить, не заменять стандартными:**

- `server-settings.json` и свою конфигурацию окружения/службы
- Свои корневые `logo.png`, `banner.png`
- `data/`, включая master, `admin-auth.json`, `player-access.json`, модерацию, статистику и скрипты
- `world/` и другие настроенные хранилища
- `client-resources/`, свои моды, плагины, `gamemode.js`
- Журналы, собственные пакетные файлы/зависимости

Частный `.runtime/` можно сохранить; стартер его проверяет. Новые стандартные скрипты переносите после сравнения по отдельности, не заменяя свои каталоги. Launcher обновляется отдельно; в серверных архивах нет launcher EXE.

**r5 требует Steam при каждом входе.** Добавьте Steam Web API Key в CFG/Доступ и вход, выберите режим. Предоставьте новую EXE launcher и подходящий клиент. Старые клиенты обязательную проверку не выполнят. Гостевые профили отдельные; существующие профили аккаунтов автоматически не мигрируют. См. [Steam и вход](docs_ingame_login.md).

<a id="start-und-kontrolle"></a>

## Запуск и проверка

Выполните `sh ./start-test-server.sh` или `start-test-server.bat` в серверном каталоге. systemd должен вызывать стартер с правильным рабочим каталогом, например `ExecStart=/bin/sh /opt/skymp/start-test-server.sh`. После изменения службы — `sudo systemctl daemon-reload`.

Прямой `node dist_back/skymp5-server.js` обходит независимое управление и его Discord-бота.

1. Проверьте прежний вход. Если неожиданно появился мастер первой установки, сначала проверьте рабочий каталог и `data/admin-auth.json`.
2. Остановите игру: dashboard, журналы, настройки, загрузки должны остаться. Запуск/перезапуск меняет только игру.
3. Настройте или проверьте Discord в Настройки/CFG/Discord, укажите статус-канал. Сохранение применяет сразу. Проверьте соединение и реальные сообщения запуска/остановки/перезапуска.
4. Игровое соединение и загрузки проверьте отдельно совместимым клиентом. Локальные тесты пакета/SDK не заменяют приёмку VPS.

Новые входящие порты не нужны: тестовые `7777/UDP`, `8080/TCP`; HTTPS использует прежний proxy. Discord требует исходящие HTTPS/WSS TCP 443 и DNS. Подробнее в `PORTS-VPS.md`, `DISCORD-BOT.md`.
