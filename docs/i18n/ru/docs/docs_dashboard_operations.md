# Dashboard и перезапуски игрового сервера

Состояние на 26 октября 2026 года. Dashboard сравнивался в режиме чтения с работающим txAdmin 8.1.1 оператора. Сервер RedM и его настройки не изменялись. Интерфейс SkyMP использует собственные компоненты и комплектный логотип сервера.


**Настройки → Безопасность** (`#settings/security`) управляет защитой консоли и от читов в Core. Требуются роль администратора и `canConsole`. Сохранённые значения и активная конфигурация, подтверждённая нативным игровым сервером, показываются раздельно; изменения требуют его перезапуска. Клиентские сообщения о найденных перехватчиках — неподтверждённые самоотчёты. Защита работает без Chat и не меняет его `/`-команды. Миграция, режим разработки и ограничения анализа движения описаны в [Console Security](docs_console_security.md).

**Журнал сервера** получает новые консольные и административные сообщения также через активное WebSocket-соединение. Живая консоль и HTTP-список журналов остаются доступны. Консольные сообщения JavaScript записываются один раз в терминал и JS-журнал; дополнительная копия через нативный logger убрана. Регулярные успешные heartbeat к master журналируются не чаще раза в пять минут. Запуск, завершение, ошибки и восстановление по-прежнему фиксируются; сам интервал heartbeat не изменён.

Быстрое действие **Отправить объявление** отправляет сообщение всем подключённым игрокам баннером вверху игрового экрана. Баннер виден восемь секунд; существующий клиент ограничивает текст 240 символами. Dashboard использует существующий пакет `announcementToast`. Необязательные адаптеры Chat могут дополнительно вывести сообщение в чат. Для этого исправления нужно обновить и перезапустить серверные программы; менять нативную клиентскую DLL не требуется. Локальные HTTP/браузерные проверки не заменяют тест в Skyrim/CEF.

**Ресурсы → Серверные плагины** показывает расширения из `Plugins/`, обнаруженные при запуске игрового сервера. Для каждого доступны **Включить** и **Отключить**. **Включить все отключённые** разрешает все обнаруженные плагины с `plugin.json`, включая скрытые поисковым фильтром. В разделе **Новые плагины при запуске игрового сервера** вместо стандартного подтверждения в dashboard можно выбрать **Включать автоматически**. Тогда новые плагины загружаются сразу при первом обнаружении. Ранее известные отключённые остаются отключёнными до индивидуального или общего разрешения. Разрешение сохраняется; команда терминала при каждом запуске не нужна. Текущий статус и разрешение запуска показываются отдельно. Для этих изменений достаточно перезапуска игрового сервера. Формат поставки, первая установка и ограничения описаны в [руководстве по плагинам](../README-plugins.md).

**Ресурсы → Игровые моды** управляет дополнительными модами. Пять обязательных файлов Skyrim не предлагаются как выбираемые моды и при сохранении автоматически остаются в начале порядка загрузки.

**Dashboard** теперь показывает те же реальные измерения процессов и тиков, что и **Метрики**, с историей и выбираемым временем. Добавлены зарегистрированные отключения за последние шесть часов, отдельно ожидаемые и неожиданные. Время начала наблюдения показано; отсутствующие часы не считаются безошибочной работой. Определения измерений, проценты CPU и пробелы описаны в [руководстве по метрикам](docs_server_metrics.md). Ниже можно раскрыть сведения сервера и собственные разрешения.

**Настройки** сразу открывают общие разделы **Общие**, **Игровой сервер**, **Доступ**, **Discord**, **Мир** и **Исходный JSON**. CFG-редактор в боковом меню ведёт прямо к JSON. Прямые ссылки: `/admin?devUi=1&admin=1#settings/general`, `#settings/server`, `#settings/access`, `#settings/discord`, `#settings/game`, `#settings/json`. Старый `#discord` продолжает работать. Discord сохраняет маскирование секретов, отдельное сохранение и проверяемый предварительный просмотр; вход в игру, включая **Legacy (skymp.net)**, настраивается в разделе доступа.

### Расписание перезапуска через форму

1. Запустите полный сервис через `launch_server.bat` или `launch_server.sh`. Откройте **Настройки → Игровой сервер**.
2. Включите расписание, выберите часовой пояс IANA, например `Europe/Berlin`, и добавьте до двенадцати ежедневных времён. Часовые пояса сервера и браузера показаны для справки. Расписание действует именно в выбранном поясе с учётом летнего/зимнего времени.
3. Выберите предупреждения и сохраните. Изменения действуют сразу. В боковой панели показано следующее срабатывание; **Пропустить ближайший** пропускает именно его. Будущие дни остаются в расписании.

Перезапускается только **игровой сервер**. Dashboard, сессии, соединение Discord, журналы, настройки и загрузки launcher продолжают работать. Намеренно остановленный, аварийно завершённый или запускающийся игровой процесс расписание не запускает. Пропущенное во время простоя срабатывание не выполняется позже. Ошибка управления процессом не приводит к автоматическому повтору уже занятого срабатывания.

Несуществующее местное время при переводе часов пропускается в этот день. Повторяющееся выполняется не более одного раза. Предупреждения передаются через частный supervisor IPC существующему клиенту (`announcementToast` и адаптеры Chat) и в настроенный канал предупреждений Discord. Дополнительные порты не нужны. Реальный вывод в игре и доставка в настоящий Discord остаются отдельными этапами приёмки.

Конфигурация хранится в `restartSchedule` файла `server-settings.json`. Форма меняет только это поле и определяет устаревшие версии. Выполненные/пропущенные срабатывания атомарно записываются в `<dataDir>/restart-schedule-state.json` до действия над процессом. При отсутствии прав записи или повреждении файла автоматические действия блокируются. Повреждённые файлы не перезаписываются. Изучите ошибку и после резервного копирования восстановите файл при остановленном полном сервисе.

Статистика отключений находится в `<dataDir>/dashboard-activity.json`: максимум 5 000 событий за последние шесть часов, только время, тип и сокращённая причина, сообщённая игрой. IP, SteamID и данные входа не добавляются. При ошибке записи отображение продолжает работать в памяти и сообщает об этом. Резкое завершение может потерять последние две секунды. Перезапуск игрового сервера сохраняет данные в веб-процессе.

**При обновлении:** остановите весь сервис, замените файлы из Update ZIP для нужной ОС и запустите снова. Сохраните `server-settings.json` и весь собственный `data/`, включая оба файла. Full ZIP предназначены для первой установки. В них нет предустановленного администратора или активного расписания перезапуска. См. [руководство по обновлению](docs_packaged_server_update.md).

### Интерфейсы

Все конечные точки требуют существующей административной сессии. Чтение требует `canViewLogs`, изменения — роли администратора и `canConsole`.

| Метод и путь | Поведение |
| --- | --- |
| `GET /api/admin/overview` | Суммарная статистика отключений за шесть часов и начало наблюдения |
| `GET /api/admin/server/restart-schedule` | Конфигурация, ревизия, ближайшее срабатывание, часовой пояс и статус хранения |
| `POST /api/admin/server/restart-schedule` | Сохранить только `restartSchedule`; ожидает `config` и текущую `revision` |
| `POST /api/admin/server/restart-schedule/skip` | Пропустить ближайшее; ожидает текущее `nextAt` |

Запись требует JSON с того же Origin. Устаревшая ревизия или уже изменившееся срабатывание возвращает HTTP 409, неверное время или часовой пояс — HTTP 400. Настройка не является shell-командой и не может запускать произвольные программы.
