# Завершение сессии: кик, бан, перезапуск и потеря соединения

Теперь игроки узнают, когда соединение с сервером прервано. Раньше игра продолжала работать локально без какого-либо уведомления. Эта функция входит в ядро и работает без плагинов Chat и UI-Core.

## Поведение в игре

| Причина | Что видит игрок |
| --- | --- |
| Кик, бан, перезапуск или остановка сервера | Немедленное завершение сессии: управление заблокировано, возврат в главное меню, оверлей с причиной |
| Потеря соединения во время игры | Уведомление о переподключении, автоматические попытки до 30 секунд, игрок остаётся в мире. При неудаче: главное меню и оверлей |
| Ошибка соединения до начала игры | Оверлей в главном меню, без автоматических попыток |
| Отказ в соединении при переподключении | Немедленное завершение сессии, так как новая попытка ничего не изменит |

Сообщение сервера (кик, бан, перезапуск) во время переподключения сразу прекращает попытки. Если сервер принял соединение, срок продлевается минимум до 15 секунд, чтобы завершился вход. О неверном пароле по-прежнему сообщает диалог входа.

В оверлее есть два действия:

- **Главное меню** закрывает уведомление без переподключения. Это сделано намеренно: с профилями Steam и офлайн новый вход начался бы сразу и снова подключил бы кикнутого игрока.
- **Подключиться снова** начинает новую сессию. Во время действующего бана это действие недоступно.

Оба действия становятся доступны в главном меню либо не позднее чем через 15 секунд после завершения сессии, если возврат в главное меню не завершился. Действующий бан хранится до истечения срока, а постоянный бан до перезапуска игры. Сам бан обеспечивает сервер.

## Сообщение сервера

Сервер отправляет надёжный CustomPacket и закрывает соединение через 150 мс. Для этого `server.kick` обёрнут, поэтому все существующие вызовы автоматически отправляют уведомление. Плагины менять не нужно.

```json
{"customPacketType":"skymp:sessionEnd","version":1,"kind":"kick","message":"","until":null}
```

`kind` принимает значения `kick`, `ban`, `restart` или `shutdown`. `until` задаётся только для временных банов. Отображаемый текст фильтруется, ограничен 512 символами и выводится как текст.

Сервер отправляет уведомление при SIGTERM, то есть при управляемых перезапусках через супервизор, и при SIGINT (Ctrl+C). После сбоя или `kill -9` он уже ничего отправить не может. Тогда потерю обнаруживают клиентский heartbeat (`skymp:sessionPing`/`skymp:sessionPong`, 15 секунд) или нативный тайм-аут. Старые серверы без pong используют только нативный тайм-аут.

## Технические ограничения

Вызовы Papyrus разрешены только в событии `update`, а `update`, насколько сейчас известно, не выполняется в главном меню. Поэтому в `sessionEndClient.ts`:

- Состояние меню берётся из `menuOpen`/`menuClose`, а не из `Ui.isMenuOpen`.
- Оверлей и переподключение работают в `tick`.
- Только `quitToMainMenu` и управление игроком используют `update`.

`NetworkingService.close()` выполняет тихую остановку транспорта для процесса входа и не завершает сессию.

## Тесты

```powershell
npm --prefix skymp5-client run test:session-end
```

Тестовый мок выбрасывает ошибку при вызовах Papyrus вне `update` и не вызывает `update` в главном меню, как и в реальной игре. Ещё нужно проверить вручную в игре: кик, бан, плановый перезапуск, остановленный процесс сервера и короткий сбой сети.
