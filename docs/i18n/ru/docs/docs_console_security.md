# Безопасность консоли SkyMP

<a id="verifizierte-ausgangslage-und-eingriffspunkte"></a>

## Проверенное исходное состояние и точки интеграции

Анализ от 29.10.2026 до реализации:

- Нативные консольные пакеты проходят путь `ConsoleCommandsService` → `MsgType.ConsoleCommand` → `ActionListener::OnConsoleCommand` → `ConsoleCommands::Execute`. Сервер уже определяет актёра по соединению, однако старый переключатель `enableConsoleCommandsForAll` полностью обходит `EnsureAdmin`.
- Пять существующих серверных операций пока не имеют полной предварительной проверки количества аргументов, диапазонов целых чисел и неизвестных подкоманд `mp`. Серверное разрешение актёра — `consoleCommandsAllowed`; установить этот флаг может только доверенный серверный API.
- `MovementValidation::Validate` защищает смену ячейки/мира и скачки позиции от 4096 единиц. Анализ по времени и проверка неконечных координат отсутствуют. Сейчас `OnUpdateMovement` отправляет данные соседям до проверки; порядок нужно исправить.
- `findConsoleCommand` находит короткие и полные имена. Если `execute` возвращает `false`, SkyrimPlatform не выполняет исходную команду. Существующий API позволяет вызывать прежний обработчик по цепочке; при перезагрузке скриптов SkyrimPlatform удаляет перехватчики.
- `Settings` и нативный `ScampServer` получают один и тот же `server-settings.json`. В dashboard уже есть аутентифицированные маршруты, `canConsole`, навигация настроек и IPC между игровым сервером и dashboard. Сохранённую политику и фактически активную в нативном процессе необходимо показывать раздельно.
- Отдельный `D:/GitHub/SkyMP-Chat` использует CustomPacket `skympChat:*`, работающую `CommandRegistry` и синхронный resolver разрешений. Эти пути не связаны с нативным пакетом ConsoleCommand. Для этой функции репозиторий Chat только изучается; второй реестр и новый диспетчер чата не создаются.
- Сообщения инвентаря, хостинга актёров, попаданий и атрибутов имеют собственные нативные пути обработки. Защита консоли не заменяет и не отключает их проверки. Существующая регенерация атрибутов и сопоставление актёра/хоста сохраняются.

<a id="umsetzungsgrenzen"></a>

## Границы реализации

Решение о привилегированных изменениях состояния принимает сервер. Клиентские перехватчики — дополнительная защита, а не основание доверия. Без запросов геометрии/коллизий полное обнаружение noclip невозможно. Эвристики движения первоначально служат наблюдению; автоматические баны не предусмотрены. Разрешены целевые тестовые сборки C++, но релизные сборки и ZIP исключены.

<a id="konfiguration-und-migration"></a>

## Конфигурация и миграция

```json
{
  "consoleSecurity": {
    "mode": "restricted",
    "blockVanillaCheats": true,
    "blockUnauthorizedServerCommands": true,
    "monitorMovement": true,
    "movementEnforcement": "monitor",
    "logViolations": true,
    "logAllowedAdminCommands": true
  }
}
```

Это также значения по умолчанию при отсутствии конфигурации. При запуске неверные значения сопровождаются диагностикой и заменяются безопасными; dashboard отклоняет их при сохранении. Неизвестные поля внутри `consoleSecurity` диагностируются при запуске или отклоняются при записи через API. Остальные настройки сервера сохраняются.

`restricted` принудительно устанавливает `blockVanillaCheats:true`. В режиме `development` оператор может явно отключить эту клиентскую защиту. **Оба режима по-прежнему требуют серверной авторизации.** `blockUnauthorizedServerCommands:false` не является поддерживаемым отключением: при запуске значение игнорируется с диагностикой, при сохранении отклоняется.

`enableConsoleCommandsForAll:true` и неверные устаревшие значения дают `LEGACY_CONSOLE_BYPASS_IGNORED`. Новая политика всегда имеет приоритет. Переключатель остаётся видимым в существующих файлах, но больше не предоставляет прав. Если раньше он открывал административные команды всем игрокам, теперь права нужно явно выдавать на сервере:

```js
// Nur im vertrauenswürdigen Server-/Gamemode-Code, nach eigener Autorisierung:
mp.set(actorId, 'consoleCommandsAllowed', true);
```

Этот флаг не является ролью, передаваемой клиентом. Права администратора dashboard и права персонажа разделены; режим разработки не предоставляет ни те ни другие. Данные существующих персонажей и пользователей не удаляются и не переписываются автоматически. Изменения политики вступают в силу после перезапуска игрового сервера. При первом развёртывании нужно обновить нативный серверный модуль, общую клиентскую JS-runtime и исправленную консольную привязку SkyrimPlatform.

<a id="native-befehle-und-bestehende-handler"></a>

## Нативные команды и существующие обработчики

Обычный клиент блокирует поддерживаемые команды `tcl`, `tgm`, `tim`, `modav`, `setav`, `forceav`, `setlevel`, `coc`, `moveto`, `kill`, `resurrect`, `enable` и `unlock`. Короткие и полные имена определяются по фактической таблице команд. Синтаксис ссылки/`player.` попадает в ту же нативную команду. Отсутствующие записи отмечаются как неподдерживаемые, а не защищённые. Безопасные команды, например `help`, не переопределяются.

Существующие серверные операции `additem`, `equipitem`, `placeatme`, `disable` и псевдоним `mp disable` остаются отдельными авторизованными серверными запросами; их исходное локальное выполнение в vanilla не разрешается. Через привязанный к соединению handshake Core клиент получает текущие разрешённые операции над собой. Сервер повторно проверяет каждый реальный запрос, включая цель. Клиентское разрешение не является авторизацией.

До выполнения сервер проверяет известные имена, точное количество аргументов, целочисленные типы, положительные 32-битные ID форм и количество от 1 до 1 000 000. Неизвестные подкоманды, переполнения и отрицательные количества отклоняются. Отсутствующие базовые записи отклоняются до вызовов Papyrus. Идентичность берётся только из сопоставления соединения и актёра. Неизвестные или неаутентифицированные соединения не получают привилегированных побочных эффектов.

Существующие нативные JS-обработчики вызываются по цепочке. Повторный поиск или псевдоним возвращает ту же внутреннюю запись команды SkyrimPlatform, не заменяя прежний обработчик и исходную нативную функцию. Исправление также предотвращает рекурсию, если вход trampoline был бы сохранён как исходная функция.

<a id="bewegungsanalyse-und-grenzen"></a>

## Анализ движения и ограничения

Существующие проверки смены ячейки/мира и шага в 4096 единиц сохраняются. Неконечные позиции/повороты отклоняются. Данные движения передаются соседям только после успешной проверки. Неконечные проценты атрибутов и значения вне 0–1 также не должны менять серверное состояние актёра.

- `off` или `monitorMovement:false`: дополнительное наблюдение по времени отсутствует; базовые проверки состояния активны.
- `monitor`: записываются консервативные наблюдения скорости/движения вверх по серверному времени получения; эвристическая коррекция движения не выполняется.
- `enforce` (устарело): при загрузке обрабатывается как `monitor` и больше не предлагается в dashboard, так как этот режим никогда не был строже. Эвристики скорости/подъёма не приводят к отклонению или бану. Статус сообщает `heuristicEnforcement:false`.

Окна наблюдения короче 100 мс и длиннее трёх секунд пропускаются; образцы позиции обновляются не чаще одного раза в 250 мс. Заявления клиента о скорости, прыжке или ездовом животном не позволяют обойти проверки. Большие прыжки, отбрасывание, скриптовое движение и задержки всё же могут вызвать наблюдения. Серверные телепорты сохраняют существующую коррекцию/ресинхронизацию и при этом не записываются как нарушение с читами.

Доверенный серверный код может освободить актёра от дополнительных эвристических наблюдений максимум на 30 секунд. Это не разрешает смену ячейки, неконечные координаты или запрещённый скачок позиции. При удалении актёра удаляются образцы и исключение. Новый режим noclip и проверки коллизий по геометрии не реализованы.

<a id="dashboard-und-status"></a>

## Dashboard и статус

**Настройки → Безопасность → Защита консоли и от читов**, прямая ссылка `#settings/security`. Требуются существующая административная сессия, роль администратора и `canConsole`. Интерфейс показывает рядом сохранённые значения и активные значения, подтверждённые нативным процессом. Отличия требуют перезапуска игрового сервера. Для остановленного или устаревшего нативного процесса активная защита не заявляется.

`GET /api/admin/console-security` читает это состояние. `PUT` принимает только `{revision, consoleSecurity}` в JSON с соответствующим Origin. Устаревшая ревизия возвращает HTTP 409, отсутствие прав или неверный Origin — HTTP 403, неверные значения — HTTP 400. В самой свежей версии файла заменяется только объект безопасности. Повторно используются существующее хранилище конфигурации, журнал изменений и IPC игрового сервера/dashboard.

Клиентские отчёты содержат найденные и неподдерживаемые перехватчики и время. Они явно показаны как **неподтверждённые самоотчёты**. Модифицированный клиент может их подделать. Даже `supported` не доказывает, что другой мод позже не заменил перехватчик, и не гарантирует полной защиты от noclip.

<a id="optionale-plugin-berechtigungen"></a>

## Необязательные разрешения плагинов

Серверный интерфейс Core `globalThis.skympConsoleSecurity` имеет API версии 1. Он не зависит от Chat и не предоставляет реестр команд:

```ts
interface PermissionContext {
  userId: number;
  actorId: number;
  profileId: number;
  targetId: number;
  permission: string;
  source: 'native_console' | 'plugin';
}
```

`setPermissionResolver(owner, resolver)` принимает ровно один синхронный resolver, закреплённый за владельцем. `true` разрешает, `false` запрещает, `null`/`undefined` возвращается к существующему флагу актёра для нативных команд. Исключения, Promise и рекурсивные вызовы запрещают доступ. Другой владелец не может заменить resolver; текущий удаляет его через `null`. При перезагрузке gamemode регистрация сбрасывается.

`hasPermission(userId, permission)` определяет актёра и профиль на сервере для будущих адаптеров плагинов. Без resolver только известные `console.additem`, `console.equipitem`, `console.placeatme` и `console.disable` могут быть разрешены серверным флагом актёра. Остальные разрешения по умолчанию запрещены. `grantMovementAllowance(actorId, milliseconds)` устанавливает или отменяет описанное исключение в диапазоне 0–30 000 мс. `getStatus()` возвращает состояние Core.

Будущий плагин ролей может явно связать **уже существующий** resolver Chat:

```js
// Optional im eigenen serverseitigen Rollen-Plugin; Core setzt dies nicht voraus.
const core = globalThis.skympConsoleSecurity;
const chat = globalThis.skympChat;
if (core && chat) {
  chat.setPermissionResolver('roles', (userId, permission) =>
    core.hasPermission(userId, permission));
}
```

Существующий Chat по-прежнему самостоятельно регистрирует и выполняет `/`-команды. Автоматической связи с его resolver нет; Console Security не меняет исходный код Chat. Без Chat защита Core работает полностью.

<a id="logs-und-abnahme"></a>

## Журналы и приёмка

В существующем серверном журнале `[security]` сопровождается структурированными JSON-событиями со временем, внутренним актёром, канонической командой, причиной, источником и `blocked`. Одинаковые события ограничиваются в каждом пятисекундном окне; число подавленных повторов включается в следующую запись. Сырые аргументы, токены доступа и IP-адреса не включаются. `movement_observation` означает наблюдение, `movement_rejected` — фактическое отклонение. Клиентские отчёты записываются с `source:client_report`, `reportedBlocked:true` и **`blocked:false`**, чтобы не выдавать их за доказанную сервером блокировку.

Автоматизированные проверки находятся в `unit/ConsoleSecurityTest.cpp` и `misc/console-security/tests/`. Существующие тесты консоли, движения, атрибутов и Chat входят в регрессионную проверку. Тесты исходного кода: `npm --prefix skymp5-client run test:console-security`.

Ручная проверка остаётся для: исходных консольных команд и псевдонимов в Skyrim, `player.`/выбранных ссылок, разрешённых административных запросов, режима разработки, переключений/перезапусков/повторных соединений, внутренних телепортов SkyMP и движения с прыжками, падениями, плаванием, ездой, отбрасыванием и задержками. Клиентские перехватчики не останавливают прямые изменения памяти, альтернативные SKSE-перехватчики или уже активированные локальные читы. Исходные и модульные тесты не заменяют полную проверку Steam/Skyrim/двух игроков.

## Известное ограничение ролевого интерфейса

По каждой команде клиент узнаёт только, может ли игрок выполнить её **на себе** (`allowedServerCommands`), и пересылает её лишь в этом случае. Поэтому резолвер, разрешающий команду только для чужих целей, должен разрешить её и для собственного актора игрока. Это ограничение в пользу безопасности: команду можно ошибочно заблокировать, но нельзя ошибочно выполнить, так как сервер сам проверяет каждый запрос.
