# Frontend & Infrastructure Roadmap

This roadmap tracks the development of the admin dashboard, launcher UI, testing infrastructure, and frontend tooling for the Skyrim Multiplayer project.

## Launcher Mod Publication (2026-10-21)

- Added a separate public `/api/launcher/manifest` v2 contract and opaque file download routes with full destination paths, sizes, SHA-256, local game requirements and load order. Custom server plugins/archives and explicitly published client assets are supported; private server data and Bethesda game files are excluded.
- Updated the standalone `skymp-client-launcher` Rust downloader to preserve asset subdirectories, discover the optional client runtime package and validate the complete package before activating files or starting SKSE. Legacy server profiles remain supported. Game execution is unchanged and was not exercised.
- Windows/Linux HTTP checks and a real HTTP-to-Rust preparation test cover downloads, cache reuse/repair, package changes, failure handling and restoration. See [operator guide](docs/docs_launcher_modpacks.md). Actual Skyrim/CEF compatibility remains open.

## First Installation And VPS Access (2026-10-20)

- Separate Linux/Windows first-run packages use a browser wizard for server name, ports, player slots, local/SSH/public access, public IPv4/domain, master-file readiness and an owner account. The terminal only provides the URL and a random four-digit, single-use PIN. PIN expiry, a global attempt budget, an HttpOnly session and origin/CSRF checks protect setup. No preconfigured admin account or plaintext password is included; the launcher requires setup before starting the game server. Existing admin accounts and world data are preserved. The browser packages supersede the earlier terminal-wizard packages.
- Setup writes a compatible scrypt auth store, owner roles, a configuration backup, connection instructions and an example direct-connect client configuration. Later launches keep the account. The VPS guide documents `uiListenHost`, UDP/TCP firewall rules and distinct offline test profile IDs.
- Browser setup validation: both final native packages pass real PIN-protected HTTP setup, startup with five complete master files, own-account login, frontend and UDP checks. Configuration (19 groups) and HTTP setup (10 groups) pass on Windows/Linux; five desktop/mobile wizard screens add ten axe checks with zero violations and recorded incomplete gradient-contrast findings. The complete browser flow also checks invalid codes, session resumption, missing/invalid masters and mismatched passwords.
- Older release directories were removed at the user's request; that cleanup retained `2026-10-20-browser-setup`, including public baseline receipts. The separate full Windows native suite passes 263/264 cases on NTFS; the existing real-time 25ms `Activate torch` assertion also fails in isolation and remains open. Installation/startup success is recorded separately from full native-suite qualification.
- The user's VPS terminal log confirms native Linux startup with five masters and the saved admin auth store. A subsequent public HTTP check returns 200 for the real admin login page and confirms setup is complete. A real Skyrim client connection and load test remain pending; the known local Skyrim runtime incompatibility remains deferred.

## Mobile And Accessibility Checkpoint (2026-10-19)

The first core-screen pass is implemented; full application coverage remains open.

- Launcher controls fit 360px widths and scroll vertically; wide tables scroll locally. The admin dashboard can scroll as a whole on phones, including its controls and navigation.
- Shared modal handling provides initial focus, Tab/Shift+Tab containment, top-dialog Escape, background isolation and focus restoration, including profile-to-warning transitions. Update/warn/profile, admin-user and whitelist dialogs use the same handling as the launcher and dashboard.
- Dashboard/profile tabs support Left/Right and Home/End. System disclosure state, tab relationships, profile field names and close labels are accessible. New labels cover all six locales.
- Light/dark launcher and moderation-control contrast issues were corrected. The profile opens from the existing player list instead of a duplicate heading table.
- Admin-user create/edit forms now support Enter submission, named close controls, focus restoration and scrollable content on short screens. Invalid Discord IDs block writes; server errors stay inside the active dialog and preserve the entered data. Save controls and fields reflect pending requests.
- Configuration tabs expose their associated panels and support Left/Right and Home/End. Inventory controls have localized labels, the inventory scroll area is keyboard focusable, and configuration feedback is announced as a status. Narrow layouts wrap action toolbars and keep JSON input inside its panel.
- Whitelist approval uses a labelled identifier field, Enter submission, inline errors, pending-state guards and a scrollable dialog. Failed saves retain the identifier; Escape restores the approval button. The panel search has an accessible name, narrow footers wrap, and approved entries can be scrolled by keyboard.
- The actual server-rendered admin entry page now has the correct document language, a main landmark, announced errors, visible focus and a layout that scrolls on short screens. Login/setup/migration initialize before submission is enabled; pending requests disable competing controls. Migration distinguishes old/new passwords, and setup exposes minimum length and confirmation requirements. The template lives in `skymp5-server/ts/adminLoginPage.ts`, shared by the `/admin` route and browser tests.
- The active in-game login is the form widget generated by client `AuthService`, using OAuth and existing native events. Unreferenced React email/password login/register demos were removed; startup removes their old plaintext `localStorage.password` key. Their shared control styles were preserved under `components/WidgetForm/legacyControls.scss`.
- `WidgetForm` now renders game forms with a scrollable card, wrapping labels/text, visible keyboard focus, persistent focus on status refresh, and accessible input/checkbox controls. Shared buttons use native disabled semantics; client login comments are exposed as a live status. The previous conditional form hooks and content-based widget keys were replaced by a separate form component and stable widget IDs.
- `npm run test:a11y` extends the existing mock-backed browser smoke with axe WCAG A/AA checks, viewport bounds and keyboard interactions at 360px and 1280px. Scope: launcher (both themes), players, respawn, events, warn dialog, identifiers/notes/history profile tabs, admin-user create/edit/error states, General/Access/World/JSON configuration tabs, whitelist panel/dialog/error/populated states, and admin login/error/setup/migration screens. Reports/screenshots are stored in `.cache/accessibility/`; incomplete axe findings remain available for manual review.
- Browser regression checks cover admin-user creation, role editing, rejected saves, cancellation without a write, and configuration saving while preserving unrelated JSON fields. All writes in these tests use simulated API routes.
- Whitelist tests cover invalid identifiers, rejected/retried writes, refreshed entries and cancellation. Admin authentication tests use the real rendered template with simulated endpoints: invalid login, prevention of duplicate pending requests, setup password length/mismatch, legacy migration payloads, return to login and the Discord entry redirect. These checks do not exercise a live Discord authorization callback or create actual accounts.
- Game-widget tests extract the actual client login factory and verify sign-in, configured-server selection, server keys, Play events, status/focus refresh, password-key removal, labelled inputs, checkbox keyboard interaction and skipping disabled actions. Login, authenticated state and generic game form fields add six axe checks.
- Remaining: other admin forms and device widths, live OAuth callback validation, manual screen-reader and Skyrim/CEF checks. The mobile/a11y roadmap items therefore stay **In Progress**.
- Validation: frontend/server production builds, size budget, TypeScript, regular lint, locale/component tests and API tests pass; the updated client plugin also builds successfully. All 54 axe checks report zero violations; keyboard/moderation/form/authentication/game-widget flows and a separate desktop run under `/game/ui/` pass. Gradient/overlap contrast findings marked incomplete by axe remain in the reports for manual review. The verified frontend is included in both server test packages. The Linux-native Release build, 264 native test cases (476,480 assertions in the retained complete log), and actual server startup/admin login/frontend delivery under Ubuntu 26.04 pass. See the [native validation report](docs/docs_native_validation_2026_10_19.md) and [Linux VPS guide](docs/docs_linux_vps.md) for the paired Linux/Windows test builds. Native startup on the physical 12-vCore/24-GB VPS is confirmed by the user log and public admin HTTP check. Load testing and Skyrim/CEF validation remain open; game startup was deferred at the user's request.

## Production Build Checkpoint (2026-10-19)

The production-build and bundle-monitoring baseline is implemented. Runtime code
splitting/lazy loading and the 500 KiB gzip target remain open.

| Measurement | Previous development bundle | Production bundle |
| --- | ---: | ---: |
| JavaScript bytes | 5,845,671 | 3,451,700 |
| JavaScript gzip bytes | 1,153,515 | 813,004 |

- `npm run build` uses production mode; `build:dev` and all dev-server commands use development mode.
- `bundle-size.json` records per-file raw/gzip sizes and totals for emitted JavaScript. The production baseline guard is 850 KiB gzip (870,400 bytes), including future lazy chunks. Images/audio/maps are outside this JavaScript budget.
- The guard runs in existing CI prechecks that build this checkout; CMake packaging includes the report with the prebuilt frontend assets. `npm run test:bundle` verifies rejection above the production budget, inclusion of lazy chunks, and unrestricted development builds.
- The single `build.js` entry and current server/Skyrim UI packaging are retained. Gzip is a measurement, not an assumption about server compression.
- Next optimization phase: reduce the remaining JavaScript payload toward 500 KiB, with browser and game-UI asset-path checks before introducing runtime chunk downloads.
- Verified: production build/budget, lint, TypeScript, locale/component tests, API tests, and the launcher/admin browser smoke against the production output at both `/` and `/game/ui/` (simulated API/WebSocket responses). The production bundle and report were copied into the local server distribution and verified by hash. An actual Skyrim/CEF session was not tested.

## Architecture Notes

### Technology Stack

- **React 18** - UI framework with functional components and hooks
- **TypeScript 5.9.x** - Type safety and developer experience
- **Webpack** - Module bundler with HMR support
- **i18next** - Internationalization library
- **React-i18next** - React integration for i18n
- **SCSS** - Styling with nesting and variables
- **Koa** - Backend server for admin API

### Project Structure

```
skymp5-front/
├── src/
│   ├── components/        # Reusable UI components
│   ├── features/          # Feature modules (dashboard, launcher, skills)
│   ├── interfaces/        # TypeScript interfaces
│   ├── locales/           # i18n translation files (en/ru/de/es/fr/it)
│   ├── services/          # API calls, utilities
│   ├── App.js             # Main app component
│   └── index.tsx          # Entry point
├── scripts/               # Build and automation scripts
├── public/                # Static assets
├── package.json
└── tsconfig.json
```

### Performance Targets

- Initial load time: < 2s (with network throttling)
- Time to interactive: < 3s
- JavaScript bundle size: < 500 KiB gzip (optimization target; current production baseline is 813,004 bytes)
- Lighthouse score: > 80 across all categories
